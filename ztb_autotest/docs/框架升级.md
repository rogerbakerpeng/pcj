# 框架升级

每个项目一份 ztb_autotest，里面既有**框架**（所有项目共用的规则、提示词、工具），也有**项目自己的内容**（配置、学到的页面方法、造数方法、需求文档、沉淀的用例）。
升级时只换框架，项目内容不动。哪些文件属于哪一层，见根目录 `framework.yaml`。

## 三层

| 层 | 包括 | 升级时 |
|---|---|---|
| 框架层 | `AGENTS.md`、`prompts/`、`tools/`、`common/`、`conftest.py`、大部分 `docs/` | 直接替换（替换前自动备份） |
| 模板层 | `project.yaml`、`项目规则.md`、`pages/`、`flows/`、`api/`、`ws/`、`samples/index.yaml`、`docs/源码地图.md`、基线用例等 | 项目没改过的直接更新；改过的保留项目版本，新模板放到 `.framework/pending/` 对照合并 |
| 项目层 | `requirements/`、`用例库/`、`testcases/modules/`、`samples/files/`、`.env` 等 | 从不改动 |

**项目里不要改框架层的文件**，改了会在升级时被替换。项目特有的规则写 `项目规则.md`；页面方法写 `pages/base_page.py`（框架基类在 `common/ui_base.py`）。

## 怎么升级（项目里的人做）

1. 把新版本 zip 放到 ztb_autotest **外面**（不要解压覆盖）
2. 先预览，不改任何文件：

   ```bash
   cd ztb_autotest
   python tools/upgrade.py <新版本.zip>
   ```

3. 看一眼预览里「框架层：本地改过」那一项：有的话，说明项目里有人改过框架文件，升级会替换掉（旧内容会备份），需要的改动要移到 `项目规则.md` 或项目层
4. 确认后执行：

   ```bash
   python tools/upgrade.py <新版本.zip> --apply
   ```

5. 有「需要对照合并的模板」时，按脚本最后给出的那段话交给 AI 合并
6. 验证：`python tools/preflight.py --common`、`pytest --collect-only -q`

Windows 示例（cmd 或 PowerShell 都可以；路径里有空格时加英文双引号）：

```bat
cd D:\java\git\广州交易集团\ztb_autotest
python tools\upgrade.py D:\下载\ztb_autotest_20261120.zip
python tools\upgrade.py D:\下载\ztb_autotest_20261120.zip --apply
```

Windows 上的注意事项：
- 升级前关掉正在打开 ztb_autotest 文件的编辑器窗口，被占用的文件会写入失败
- 项目放在很深的目录下时，备份路径可能超过 260 个字符；写入失败时把项目移到较短的路径，或开启系统的长路径支持
- git 自动转换换行符（CRLF）不会被当成「本地改过」
- 命令行里中文显示成问号不影响结果，可以先执行 `chcp 65001` 切到 UTF-8

在 git 仓库里的，升级前后各提交一次，出问题可以直接回退；不在 git 里的，脚本备份在 `.framework/backup/`。

## 第一次从旧版本升级

旧版本里还没有升级脚本。把新版本**解压到项目外面**，用新版本里的脚本，指定项目目录：

```bash
python <新版本目录>/tools/upgrade.py <新版本目录> --project <项目的 ztb_autotest 目录>            # 预览
python <新版本目录>/tools/upgrade.py <新版本目录> --project <项目的 ztb_autotest 目录> --apply    # 执行
```

Windows 示例：

```bat
python D:\下载\ztb_autotest_新版\tools\upgrade.py D:\下载\ztb_autotest_新版 --project D:\java\git\广州交易集团\ztb_autotest --apply
```

旧版本没有安装记录，脚本无法判断文件有没有被改过，会比较保守：
- 框架层内容不同的照样替换（旧内容备份在 `.framework/backup/`）。试点中 AI 改过的框架文件（如给 `common/config.py` 加读 `.env`）会被换成新版本，新版本已包含这些能力
- 模板层内容不同的一律保留项目版本、新模板放进 pending 供对照，这次合并量会大一些

之后的升级就只处理真正有变化的文件。

## 发布新版本（框架维护者做）

1. 在框架的「干净副本」上修改，改 `framework.yaml` 的 `version`（用日期，如 `2026.11.20`）
2. 新增文件时，确认它在 `framework.yaml` 里归到了正确的层；没归类的会被当作项目层，升级时不会替换
3. 执行 `python tools/upgrade.py --record` 生成安装记录，再打包
4. 在下面的变更记录加一行
