# 提示词模板三：验收后沉淀

使用人：交付验收通过后使用，交付和研发共同确认结果。
产出物：更新 `用例库/<模块>.md`，输出 `requirements/<需求名>/04_沉淀记录.md`。

---

```markdown
你是一名测试资产管理员，负责把本次需求的测试用例沉淀到模块用例库。
用例库按功能点组织，反映功能的当前行为，不按需求堆积。

【模块】[如：实名认证]
【本次需求】[需求名称]
【本次测试用例】
[粘贴 02_测试用例.md]
【验收记录】
[粘贴 03_验收记录.md；没有填“无”]
【现有模块用例库】
[粘贴 用例库/<模块>.md；新模块填“无”]

## 处理要求
1. 验收记录中返工分类为「用例遗漏」「用例错误」的问题，先补成用例或修正用例；「需求理解」「设计」类问题，提出对检查清单（模板一分析维度）的改进建议
2. 本次每条用例归为一类，并说明理由：
   - 回归用例：长期有效、值得每次回归（通常是 P0/P1）→ 合并进用例库
   - 一次性用例：只需验证一次（如单纯的样式调整）→ 不沉淀
3. 与现有用例库比对：
   - 重复：保留一条，合并预期结果
   - 冲突：本次需求改变了原有行为 → 列出旧用例编号、旧预期、新预期、修改建议
   - 失效：功能已删除或被替代 → 建议删除并说明原因
4. 修改和删除只给建议，标注「待确认」，不直接执行

## 输出（正文只写结论，推理放附录；04_沉淀记录.md 正文不超过 60 行）

04_沉淀记录.md 结构：
- 一、结论：新增 x 条、合并 x 条、未沉淀 x 条、待确认修改 x 条（一句话一项）
- 二、沉淀明细表：| 本次用例编号 | 处理结果（新增/合并/未沉淀） | 用例库编号 | 说明（一句话） |
- 三、待确认清单：| 旧用例编号 | 建议（修改/删除） | 理由（一句话） |
- 四、流程改进建议：来自验收记录返工分类，对检查清单、02 自查项的改进（没有写「无」）
- 附录：比对过程、冲突分析等推理内容

同时输出：
1. 更新后的模块用例库（完整内容）：按功能点分组，编号为「模块缩写 + 三位序号」，已有编号不变，新用例顺延；已自动化的写明脚本位置
2. 变更记录追加一行：日期、需求、变更内容
```

---

**使用要点**：待确认清单由交付和研发确认后再修改旧用例；已自动化的回归用例确认带有 `@pytest.mark.module("<模块>")` 标记，便于下次按模块回归；`@pytest.mark.req` 标签保留，用于追溯用例来自哪个需求。
