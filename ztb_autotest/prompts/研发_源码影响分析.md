# 提示词：源码影响分析（在源码工作区使用）

使用人：研发。当 AI 在 ztb_autotest 中无法访问源码时，在**源码工程的工作区**（被测系统源码所在目录）新开会话，用这份提示词回答确认项中的研发维度问题，再把结论填回 `01_确认项.md` 的「研发补充」列。

---

```markdown
你是这个工程的资深开发。请只阅读代码，不要修改任何文件。
下面是一个需求和需要研发回答的问题，请在代码中找到依据后回答。

【需求】
[粘贴需求文档内容或需求要点]
【需要回答的问题】
[粘贴 01_确认项.md 中「回答人=研发」的问题]
【本次改动差异（可选）】
[粘贴 git diff 或合并请求链接内容；还没开发填“无”]

## 请回答
1. 相关页面和组件：文件路径、组件名
2. 现状：当前的实现逻辑（如等级怎么判断、二维码链接怎么生成）
3. 公共依赖：涉及的公共样式、公共方法、公共组件，以及还有哪些页面在用它们（列出文件路径）
4. 接口：页面调用的接口地址和关键参数
5. 页面元素：关键元素的文字、class、id 或 data-testid，供自动化定位使用
6. 影响范围结论：本次需求可能影响到的其他功能
7. 每条回答都注明依据的文件路径；找不到依据的写「未找到」，不要猜测
```
