# 样本库
> 样本**按需提供**：接入时只备挡住基线冒烟的最少几样，其余等需求用到时再放进来；AI 能自己取到的（页面接口抓包、WSDL、接口日志报文）由 AI 取。

测试要用到的**现成材料**统一放在这里：接口报文、招标文件、投标文件、文档样本、第三方提供的资料。
人按约定放进来并登记，AI 和脚本按需读取，不用每次临时去找。

```
samples/
├── index.yaml                         索引：先读它，再按需读具体文件
├── messages/                          接口报文（录制的真实报文）
│   └── <外部系统>/<接口>/<场景>.req.xml     请求
│   └── <外部系统>/<接口>/<场景>.resp.xml    返回
├── files/                             业务文件
│   ├── tender/                        招标文件
│   ├── bid/                           投标文件：normal 正常、unsigned 未签章、expired_cert 证书过期、
│   │                                  wrong_unit_cert 非本单位证书、tampered 被篡改、old_version 旧版工具、
│   │                                  broken 损坏、oversize 超大、over_price 超限价
│   └── doc/                           文档样本：Word、PDF（如文档控件保存后的文件）
└── third_party/                       第三方资料：接口文档、WSDL、控件保存请求的抓包、测试证书的说明
    └── <名称>/                        eval 评标系统、ntko 文档控件、ca 证书 ……
```

## 怎么用

**AI 和人**：先读 `index.yaml`，找到需要的条目，再读对应文件。加密的投标文件等二进制文件不用读内容，看索引里的说明。

**脚本**：

```python
from common import samples

samples.message("eval", "获取评标结果", "normal")              # 返回报文
samples.message("eval", "评标取数_项目信息", "normal", "req")   # 请求报文
samples.file("bid_normal_01")                                 # 业务文件路径
samples.entries("files", category="bid")                      # 索引条目，用于数据驱动
samples.third_party("ntko_save_req")                          # 第三方资料路径
```

mock 服务和接口客户端也从这里取报文：切换 mock 场景 `normal`，读的就是 `messages/eval/获取评标结果/normal.resp.xml`。

**检查**：`python -m common.samples` 列出已就绪、待提供的数量，以及没登记或登记了但文件不存在的条目。

## 怎么放

| 材料 | 谁提供 | 怎么取 |
|---|---|---|
| 接口报文 | 研发 | 在测试环境触发一次真实交互，从接口日志表或应用日志取出请求和返回 |
| 招标文件、投标文件 | 交付或研发 | 用招投标工具生成；异常样本（未签章、过期证书等）生成一次长期复用 |
| 文档样本 | 交付或研发 | 在测试环境操作一次，把生成的 Word、PDF 存下来 |
| 第三方资料 | 对方团队或厂商 | 接口文档、WSDL 直接要；控件保存请求用 F12 或抓包工具记录一次 |

放进来之后在 `index.yaml` 登记一行，写清来源和特点。

## 规则

1. **脱敏**：单位名称、统一社会信用代码、联系人、电话、报价换成假值；报文的结构和字段名不动
2. **不放口令和私钥**：证书私钥、密码、密钥不进样本库；需要时在 `third_party/<名称>/说明.md` 里写「放在哪里、找谁要」
3. **报文中的变量用占位符**：请求报文里每次不同的值写成 `{section_code}`、`{app_id}` 这样的占位符，脚本运行时填入
4. **异常场景**：真实环境很难取到的（超时、报错），在真实报文基础上只改必要的字段，来源写「基于真实报文修改」
5. **手写的要标明**：还没拿到真实报文时可以先手写，来源写「手写，待录制」，拿到后替换
6. **什么时候更新**：对方接口有变更；测试环境的真实对接用例失败且报文结构变了；新需求用到新的接口或场景
7. **缺样本时**：脚本会报「样本还没提供」并说明应放在哪里。这是测试数据问题，交给人提供，**不要自己伪造文件或报文**
8. **大文件**：加密投标文件默认不提交到代码仓库（见 `.gitignore`），团队内用共享目录同步；索引要提交
