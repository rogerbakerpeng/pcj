# Mock 与录制回放

本目录放**外部系统**的替身，只在本地自测使用（环境 `deps.<依赖>: mock`）。
**不要把多人共用的测试环境指向 mock**：测试环境接的是真实系统，改了会影响其他人。

## 两种测法，各管一件事

| | 本地 + mock | 测试环境 + 真实系统 |
|---|---|---|
| 验证什么 | 我们自己的代码：组装请求、解析返回、落库、异常处理 | 对接是否真的通：地址、鉴权、真实报文格式 |
| 擅长 | 异常场景（超时、报错、对方未完成） | 正常主流程，触发一次后核对数据 |
| 用例标记 | `@pytest.mark.needs("eval", mode="mock")` | `@pytest.mark.needs("eval", mode="real")` |

## mock 数据用真实报文录制，不要凭理解手写

手写的 mock 会和真实系统走偏：对方接口变了，本地照样全绿。所以 mock 不自带报文，统一从**样本库**读取：

```
samples/messages/eval/获取评标结果/<场景>.resp.xml
```

用例里切换场景 `mock.set_scenario("normal")`，mock 返回的就是 `normal.resp.xml`。新增场景只要放一个文件并在 `samples/index.yaml` 登记。
报文怎么取、怎么脱敏、什么时候更新，见 `samples/README.md`。

## 和契约保持一致

`contracts/` 下的 XSD 和规则同时用于两处：校验 mock 返回的报文、校验测试环境真实返回的报文。
这样真实接口一变，测试环境那 1～2 条真实对接用例就会报出来，再回头更新录制。

## 浏览器控件（NTKO、签章等）不在这里模拟

控件是浏览器端的第三方组件，模拟它证明不了插件能用。做法是分三段：

| 段 | 做法 | 环境 |
|---|---|---|
| 控件之前：打开的地址、参数、按钮状态 | 自动化 | 本地 |
| 控件本身：编辑、保存、转换 | 人工 | 测试环境 |
| 控件之后：附件落库、后续校验 | 自动化：用样本文件直接调用**我们应用的保存接口**（控件保存时上传的那个地址） | 本地 |

保存接口的地址和参数：在测试环境用 F12 或抓包工具操作一次控件保存，把请求记录放到 `samples/third_party/ntko/`，保存下来的文档放到 `samples/files/doc/`，脚本据此重放。

## 启动评标 mock

```bash
python -m mocks.eval_mock_server --host 0.0.0.0 --port 18080
```

本地应用的「评标系统接口地址」配置指向 `http://<本机>:18080/eval/ws`，`project.yaml` 的 `eval_mock` 填同一地址。
